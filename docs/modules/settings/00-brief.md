# ตั้งค่าระบบ (Superadmin) — Brief

<!-- Written by Claude from the user's request (2026-10-15) and the discovery answers. -->

## Goal

ให้ Superadmin ตั้งค่าข้อมูลกลางและสิทธิ์ของ BAMBAM ได้เองในแอป ไม่ต้องแก้ seed file หรือให้นักพัฒนาแก้โค้ด ใช้ร่วมกันทั้ง 3 ระบบ (แจ้งซ่อม จองรถ จองห้องประชุม)

## Problem today

- role มี 6 ตัวตายตัวในโค้ด (D-004) และกำหนดให้คนผ่าน seed file (D-014) จะเปลี่ยน role พนักงานต้องให้นักพัฒนาทำ
- master data (อาคาร ชั้น หมวดงาน อาการ) มาจาก seed (D-032) แก้ในแอปไม่ได้
- ผังอาคาร (S12) ยังไม่มีข้อมูลจริงว่ามีกี่ชั้นและแต่ละชั้นมีอะไร

## Users (rough)

- Superadmin (role ใหม่ `super_admin`): ผู้ดูแลระบบ 1–2 คน ใช้บน desktop เป็นหลัก

## Features (must have)

Request จาก user (ตามที่ส่งมา):

> เพิ่มหน้า Superadmin สำหรับตั้งค่าต่างๆ
> - ตั้งค่า Master และผังอาคารได้ ใส่รายละเอียดแต่ละชั้นได้
> - ตั้งค่า Role เป็น Matrix Permission ได้ ( เพื่มลด Role ได้ )
> - หน้าจัดการ User สามารถจัดการ ผู้เข้าใช้งานได้ ( ไว้ปรับ Role พนักงาน )

คำตอบใน discovery (2026-10-15):

- โมดูลใหม่ แยกจาก repair เพราะผู้ใช้ role และอาคารใช้ร่วมกันทั้ง 3 ระบบ
- Superadmin = role ใหม่ `super_admin`: เป็น role ของระบบ มีทุกสิทธิ์เสมอ แก้สิทธิ์หรือลบไม่ได้ คนแรกกำหนดด้วยรหัสพนักงาน
- Master: อาคาร / ชั้น + รายละเอียดชั้น (โซน/ห้อง, รูปผังชั้น), หมวดงาน / อาการ, ประเภทผู้รับเหมา
- รูปผังชั้น: 1 รูปต่อชั้น ดูอย่างเดียว เปิดดูได้จากหน้าตั้งค่าและจากภาพรวมอาคาร (repair S12)
- โซน/ห้อง: ยังไม่ใช้ในฟอร์มแจ้งซ่อม แสดงในรายละเอียดชั้นและเตรียมไว้ให้ระบบจองห้อง
- master ที่มีงานอ้างอิงอยู่: ปิดใช้งานแทนลบ
- ประเภทผู้รับเหมา: ช่างยังสร้างใหม่ได้ตอนประเมิน (D-041 คงเดิม) และ Superadmin จัดการได้ใน master
- Role matrix: สิทธิ์ระดับการกระทำ จัดกลุ่มตามระบบ เพิ่ม/ลบ role ได้ แต่รายการสิทธิ์เพิ่มได้ตอนพัฒนาเท่านั้น
- 1 คนมี 1 role (D-004 คงเดิมในข้อนี้)
- ลบ role ที่ยังมีคนใช้ไม่ได้ ต้องย้ายคนออกก่อน; `employee` และ `super_admin` ลบไม่ได้
- จัดการผู้ใช้: ค้นหา, เปลี่ยน role, ดูประวัติการเปลี่ยนแปลง (ไม่มีการกำหนด role ล่วงหน้า ไม่มีระงับการใช้งาน ไม่มี import ไฟล์)

## Nice to have (later)

- กำหนด role ล่วงหน้าก่อน login ครั้งแรก, ระงับการใช้งาน, import ไฟล์ (user ไม่ได้เลือกในรอบนี้)
- ใช้ห้องในฟอร์มแจ้งซ่อม, ปักหมุดห้องบนผังชั้น
- รูปแบบเลขที่งาน (D-015) ตั้งค่าในแอป

## Out of scope

- ตั้งค่าของระบบจองรถ / จองห้อง (ยังไม่มี brief)
- เพิ่มสิทธิ์ (permission) ใหม่จากหน้าจอ

## Constraints

- กระทบ decision ที่อนุมัติแล้ว: D-004 (role ตายตัว), D-014 (หน้าจัดการ user มาทีหลัง), D-032 (master จาก seed)
- กระทบโค้ด repair Stage 1–2 ที่เช็ค role ตรงๆ → ต้องเปลี่ยนเป็นเช็คสิทธิ์ (CR ของ repair หลัง flow นี้อนุมัติ)
