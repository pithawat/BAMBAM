## What changes

Owner's words (Thai): "ถ้าเพิ่มหมวดงานที่นี้ต้องให้ user ระบุไปเลยว่าเป็นหมวดงานที่อาคารแบบไหน ที่หน้า setting ของ admin และ super admin และอาคารต้องเพิ่ม column ระบุว่าเป็นอาคารประเภทไหนด้วย และมี table ประเภทอาคารอีกที"

The full design and the starting data are in `../../repair/changes/CR-025.md`. Settings part:

- **Building types** (`platform.building_types`): a list managed in S20, new tab `ประเภทอาคาร` (same pattern as `ประเภทอุปกรณ์`) — list (name · `{n} อาคาร` · `{n} หมวดงาน` · status), add (`ชื่อประเภทอาคาร *` ≤ 100 unique ignoring case, `หมวดงานที่ใช้ได้` check boxes, all ticked by default), rename, deactivate / activate. A type used by an active building cannot be deactivated (`ยังมีอาคารใช้ประเภทนี้อยู่ เปลี่ยนประเภทของอาคารก่อน`). No delete (BR-ALL-3).
- **Building**: every building has a required `ประเภทอาคาร *`. The S20 building rename dialog becomes `แก้ไขอาคาร` with `ชื่ออาคาร *` + `ประเภทอาคาร *` (select of active types). The building header shows the type.
- **Category** (S22): the category dialog gets a required `ใช้กับประเภทอาคาร *` (check boxes of active types, ≥ 1, error `เลือกประเภทอาคารอย่างน้อย 1 ประเภท`), replacing the optional area-type multi-select (repair CR-014). The `อื่น ๆ` category shows `ใช้ได้กับทุกประเภทอาคาร` (locked, not editable). The category header meta line shows the types as tags.
- Changing a building's type or a category's types affects new reports only; existing tickets keep their category.
- Access: `settings.locations.manage` (building types, building type field) · `settings.categories.manage` (category types) — Admin and Superadmin. Every change writes an audit row (S26).

## Why

The repair form (repair CR-025) shows only the categories used in the building's type (e.g. no ระบบปรับอากาศ in a warehouse). Admins must be able to keep that mapping and the building types right without a developer.
