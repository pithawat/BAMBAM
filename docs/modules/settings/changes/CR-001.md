## What changes

- Use a sidebar for the desktop administration area and a drawer on phones. Keep employee service navigation outside this proposal's implementation scope.
- Admin can manage buildings, floors, rooms, assets, categories, symptoms, and symptom priority. Admin cannot manage roles, permissions, or users.
- Superadmin can perform all of the above. Its own permission row stays locked on.
- Use `web ui style/manage user.png` for the visual language: white bordered panels, quiet gray canvas, blue actions, compact people rows and contextual role controls. Use `web ui style/matrix permission.png` for grouped permission tables with roles as rows and actions as columns.
- Deliver a local interactive design proposal for the four requested areas, including mobile layouts, confirmation dialogs, and access/state demonstrations.

## Why

The owner approved the previous recommendation for an administration sidebar, clarified the Admin/Superadmin boundary, and explicitly requested the UI design in this session. That authorization covers this design work without another approval request.

Risk / notes:

- Existing approved settings docs restrict the whole module to Superadmin. This CR supersedes that restriction only for the explicitly named master-data sections.
- Existing design-system layout paragraphs and settings shell descriptions predate repair CR-010. This proposal replaces desktop administration navigation; approved employee navigation is retained.
- Follow the current repair priority policy (CR-015): priority belongs to category/symptom configuration; never expose a per-ticket priority override.
- Basic reporting and following remain available to every role under the approved baseline. The prototype labels them as fixed permissions rather than silently changing that business rule.
- User identity comes from SSO. Do not copy invitation, password management, account removal, or arbitrary active/inactive states from the reference.
- New UI is a design proposal using fictional, browser-memory data. It does not implement authorization or write to the API/database.
