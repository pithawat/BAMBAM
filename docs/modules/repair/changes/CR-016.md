## Database proposal (for the owner's review before any code)

**What already exists:** `repair.buildings` (อาคาร) → `repair.floors` (ชั้น) → `platform.rooms` (ห้อง / จุด, CR-014; every floor has `พื้นที่ส่วนกลางชั้น {n}`). "ตึก" and "อาคาร" are the same level in our glossary (`building`), so the 3 levels are building → floor → room and they are already in the DB. Buildings / floors move to `platform` in settings Stage 4 (CR-007).

**Recommendation: link the asset to the room only** (not to all three). The room already knows its floor and the floor its building, so:
- one source of truth — an asset can never say "floor 5" while its room is on floor 3;
- moving an asset to another room is one column;
- "all assets on floor 3" = `assets JOIN rooms ON floor_id = …` (indexed, cheap).

If direct `floor_id` on the asset is wanted (simpler queries), add it **with a composite FK `(floor_id, room_id) → rooms(floor_id, id)`** so the two can never disagree. A `building_id` column is not needed in either case.

```
repair.buildings 1─* repair.floors 1─* platform.rooms 1─* platform.assets *─1 platform.asset_types
                          │ 1─1 platform.floor_plans              │ 0..1
                          │                                       └── repair.tickets.asset_id (new, nullable)
```

### New: `platform.asset_types` — ประเภทอุปกรณ์ (master)

| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | |
| `key` | text UNIQUE | `aircon` · `microphone` · `speaker` · `tv` (stable, used by the 3D icon) |
| `name` | text | เครื่องปรับอากาศ · ไมโครโฟน · ลำโพง · จอทีวี |
| `code_prefix` | text | `AC` · `MIC` · `SPK` · `TV` — suggests the next code (`AC-1-003`), user can type their own |
| `icon` | text | lucide icon for lists / palette |
| `mount` | text CHECK (`floor`, `wall`, `ceiling`) | default height in 3D (แอร์ = wall, ลำโพง = ceiling …) |
| `sort_order`, `is_active`, `created_at`, `updated_at` | | deactivate, never delete (D-047) |

Plus `repair.asset_type_categories (asset_type_id, category_id)` — which repair category an asset type belongs to (แอร์ → ระบบปรับอากาศ; ไมค์ / ลำโพง / ทีวี → ห้องประชุมและโสตทัศนูปกรณ์), so a QR scan (Stage 5) pre-fills the category. Kept in `repair` so `platform` never points at a repair table.

### New: `platform.assets` — อุปกรณ์ 1 ชิ้น = 1 แถว

| Column | Type | Notes |
|---|---|---|
| `id` | uuid PK | |
| `code` | text NOT NULL | the ID the user types (`AC-1-012`); unique ignoring case (`UNIQUE (lower(code))`); goes into the QR (`/repair/new?asset={code}`, D-024) |
| `name` | text NOT NULL | `แอร์ห้องประชุม 1A ตัวซ้าย` (≤ 100) |
| `asset_type_id` | uuid FK → asset_types | |
| `room_id` | uuid FK → platform.rooms NOT NULL | where it is (floor / building derived) |
| `pos_x`, `pos_z` | numeric(6,2) NULL | metres on the floor plan, origin = plan top-left, x right, z down (same as `prompt_for_3D_model/floor-plan_model.txt`); NULL = in the room but not placed on the plan yet |
| `rotation_deg` | smallint 0–359, default 0 | which way a TV / แอร์ faces |
| `is_active` | boolean | "เอาออก" = deactivate only (owner answer 3); tickets keep pointing at it |
| `created_by`, `updated_by` | uuid FK → platform.users | |
| `created_at`, `updated_at` | timestamptz | |

Indexes: `(room_id) WHERE is_active`, `UNIQUE (lower(code))`. Every add / move / edit / remove also writes `platform.audit_log` (actor, before → after), so no separate history table.

### New: `platform.floor_plans` — geometry of a floor that has a 3D plan (1 : 1 with floor)

| Column | Type | Notes |
|---|---|---|
| `floor_id` | uuid PK, FK → floors | |
| `width_m`, `depth_m` | numeric(6,2) | อาคาร 1: 32 × 15 m |
| `model_file` | text NULL | GLB of the floor (walls + baked floor texture), served like photos |
| `updated_at` | timestamptz | |

### Changed

- `platform.rooms` + `plan_shape jsonb NULL` — the room outline on its floor plan `[[x, z], …]` (metres). Used to (a) draw / colour rooms in 3D, (b) find the room under the pointer when an asset is dropped (point-in-polygon, checked again by the server), (c) place ticket pins per room.
- `repair.tickets` + `asset_id uuid NULL FK → platform.assets` — set when a ticket is reported from an asset (QR / picker). `asset_code` stays as typed. Lets the dashboard show "แอร์ตัวนี้มีงานค้าง 2 งาน".

### API (sketch, fixed after approval)

`GET /api/v1/platform/asset-types` · `GET /api/v1/platform/floors/{id}/plan` (size, room outlines, assets, model URL) · `POST /api/v1/platform/assets` · `PUT /api/v1/platform/assets/{id}` (edit / move) · `DELETE /api/v1/platform/assets/{id}` (deactivate) · repair `#27` gains per-room / per-asset open-ticket counts. Errors: `ASSET_CODE_TAKEN` (409), `ROOM_NOT_ON_FLOOR` / `POINT_OUTSIDE_ROOM` (422).
