## What changes

Owner's words (2026-11-01, summarised):

1. สแกน QR ได้บนจอโทรศัพท์ (desktop ขอไอเดีย) → **in-app camera scan on phones only**; desktop keeps the manual code card that S16 already specifies. No asset picker is added to S03.
2. สร้าง QR ของแต่ละอุปกรณ์ได้ และ print ได้ทีละอัน / ทั้งหมดทีเดียว; ใต้ QR มีตัวอักษรบอกตึก ชั้น ห้อง อุปกรณ์ แบบย่อแต่เข้าใจง่าย → **label printing inside the app** (F13-A comes into scope; D-024 had it outside the app).
3. ตอนสแกน autofill ฟอร์มยังไง → the QR holds only the asset code; the form looks the asset up live (#25) and prefills.
4. ย้ายอุปกรณ์ไปห้องอื่น ฟอร์มต้องเปลี่ยนตาม → works with no QR change because the lookup is live; assets whose label no longer matches show **"ย้ายแล้ว ควรพิมพ์ป้ายใหม่"**.
5. QR = `{FRONTEND_URL}/q/{code}` (a stable short URL that redirects to the current report form), replacing D-024's `/repair/new?asset={code}`.
6. Label printing is a **separate stage (5B)** after the scan stage (5).
7. The normal report form does **not** require an asset code (stays optional, as today).

## Why

- Labels stay on equipment for years: the printed URL must not depend on the report form's route, so `/q/{code}` only redirects and can follow any later route change.
- Admins need to label equipment without an outside tool, and know which labels went stale after a move.
- Scanning stays fast (scan → login if needed → prefilled form) and correct after moves, because nothing about the location is printed into the QR.

## Proposal (Claude)

**Stage 5 (scan, pending — not built):**
- New route `app/q/[code]/page.tsx` (outside `(app)` layout): server redirect to `/repair/new?asset={code}`. `proxy.ts` already keeps `/q/…` through login (`next=` = path + query) — no change to shared code, only verified by e2e.
- S16 accepts a QR whose origin = current origin and path = `/q/{code}`; anything else → toast "QR นี้ไม่ใช่ของ BAMBAM". `/repair/new?asset=` stays the internal URL S16 / `/q` navigate to (no printed label uses it).
- In-app scan only on phones: scan entry shows when `(pointer: coarse)` and `navigator.mediaDevices.getUserMedia` exist. Entry points: S06 report card + Home repair card, secondary button "สแกน QR" (CR-035 removed the old Home button; the bottom-nav entry went with CR-010). Desktop `/repair/scan` keeps the S16 desktop card (manual code only).
- Camera needs HTTPS (secure context) — UAT / prod must be HTTPS or only the phone's own camera works.

**Stage 5B (labels, new):**
- Where: settings, new screen **S30 พิมพ์ป้าย QR** `/settings/buildings/labels` (sub-menu of สถานที่และอุปกรณ์, `settings.assets.manage`), plus S20 row menu "พิมพ์ป้าย QR" (one asset) and a room-level "พิมพ์ป้ายทั้งห้อง".
- S30: pick building → tick floors / rooms (or "ทั้งอาคาร") → list of active assets with tick boxes, filter "เฉพาะที่ควรพิมพ์ใหม่ / ยังไม่เคยพิมพ์" → preview → พิมพ์ (browser print, CSS `@media print`, A4 sheet grid). QR generated in the browser as SVG (`qrcode` package, error correction M).
- Label (QR on top, text under it):
  - `AC-1-012` (bold, mono)
  - `แอร์ห้องประชุม 1A ตัวซ้าย` (name, max 2 lines)
  - `อ.1 · ชั้น 5 · ห้องประชุม 5B` (short location: a building name starting with "อาคาร " becomes "อ.", others kept; room name max 2 lines)
  - small: `สแกนเพื่อแจ้งซ่อม`
- After the print dialog closes: "พิมพ์ป้ายเรียบร้อยไหม" → ใช่ records a snapshot per asset (browsers cannot tell whether paper came out).
- Stale label = snapshot ≠ current: room changed → **ย้ายแล้ว ควรพิมพ์ป้ายใหม่**; code / name / building / floor / room name changed (no move) → **ข้อมูลบนป้ายเปลี่ยน ควรพิมพ์ใหม่**; never printed → **ยังไม่เคยพิมพ์ป้าย**. Computed on read, so moves from S20 (#48) and from the 3D editor (repair #32) both count with no extra code there.
