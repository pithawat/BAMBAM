# CR-002 — ออกแบบใหม่: งานของฉัน (S06), ฟอร์มแจ้งซ่อม desktop (S03) และ dropdown ทั้งหมด

Status: DONE (2026-10-14)   <!-- PROPOSED → APPROVED → DONE (or REJECTED) -->
Requested: 2026-10-14 by ผู้ใช้ (owner)
Size: S (scope) — งานเยอะ แต่อยู่ใน Stage 1 ทั้งหมด ไม่แตะ contract / DB

## What changes

1. หน้างานของฉัน (S06) — ออกแบบ UI ใหม่ โดยดูตัวอย่างจากแอปอื่นที่ use case ใกล้เคียงกัน
2. ฟอร์มแจ้งซ่อมสำหรับ desktop (S03) — ปรับใหม่ ตอนนี้ต้องเลื่อนลงดูยาวแล้วงง ให้ดูแบบที่ออกแบบไว้ดี ๆ
3. dropdown ทั้งหมด — ตอนนี้ยังไม่เรียบร้อย ออกแบบให้สวยขึ้น

## Why

ผู้ใช้ลองใช้ UI ของ Stage 1 (ก่อน wire) แล้วเห็นว่า 3 จุดนี้ยังไม่ดีพอ (2026-10-14)

ปัญหาที่ตรวจพบจริงในแอปตอนนี้ (ภาพหน้าจอ 375px / 1280px):
- dropdown: เมนูเปิดแบบ "item-aligned" ทับตัวช่องและทับ label ของช่องอื่น (ชั้น, จุดที่เกิด) · บน desktop เมนูชั้นไปโผล่ทางขวาสุด · ตัวกรอง S06 desktop สองช่องเขียน "ทั้งหมด" เหมือนกันไม่มีชื่อกำกับ และเมนูเปิดทับช่องข้าง ๆ · ตัวอักษรในเมนูเล็ก (14px) ในขณะที่ช่องสูง 52px · รายการชั้นเป็นเลขเปล่า "1, 2, 3 …" · ไม่เห็นเครื่องหมายถูกของค่าที่เลือก
- S03 desktop: 4 การ์ดเรียงลงมาสูงราว 1,700px ปุ่มส่งอยู่ล่างสุด ต้องเลื่อนลงกว่าจะเห็นว่ากรอกครบหรือยัง
- S06: แถวรายการไม่บอกว่างานไปถึงขั้นไหน ไม่มีรูป · desktop ว่างโล่ง ตัวกรองไม่มีชื่อ · งานรอตรวจรับซ้ำทั้งในการ์ดและในตาราง · ต้องเข้า-ออก S07 ทีละงาน

ค้นคว้าจากหน้าที่เปิดดูจริง (ลิงก์อยู่หัวไฟล์ mockup แต่ละไฟล์) แล้วทำเป็นตัวเลือก — เปิดไฟล์ HTML ในเบราว์เซอร์:

| เรื่อง | ไฟล์ | ตัวเลือก | Claude แนะนำ |
|---|---|---|---|
| S06 งานของฉัน | `CR-002/S06-options.html` | **A** แบ่งกลุ่มตามสถานะในหน้าเดียว (รอตรวจรับ → กำลังดำเนินการ → ปิดแล้ว 3 งานล่าสุด) + desktop รายการซ้าย/รายละเอียดขวา · **B** คงแท็บเดิม เปลี่ยนเป็นการ์ดติดตามสถานะ + desktop การ์ด 3 คอลัมน์ | **A** — พนักงานมีงานไม่กี่งาน ไม่ต้องซ่อนในแท็บ (MaintainX, Limble, NN/g) · desktop ไม่ต้องเข้า-ออกหน้า |

| Dropdown | `CR-002/dropdowns.html` | **D1** Select ใหม่ทั้งแอป (เมนูใต้ช่อง กว้างเท่าช่อง, เลือกอยู่ ≠ ชี้อยู่, > 10 มีช่องค้นหา, มือถือเป็น bottom sheet, filter pill "ชื่อ: ค่า") · **D2** (เสริม D1) ≤ 5 ตัวเลือกเป็นปุ่ม pill, 6–12 เป็นตารางปุ่ม | **D1 + D2** |

ส่วนที่เหมือนกันทุกตัวเลือก:
- ทุกแถว/การ์ดใน S06 มีรูปแรกของงาน + ตัวติดตาม 4 ขั้น (แจ้งแล้ว · ช่างรับงาน · ซ่อมเสร็จ · ปิดงาน) + นับถอยหลังปิดอัตโนมัติ — ข้อมูลมีใน `TicketSummary` แล้ว
- S03 ฟิลด์ ลำดับ และข้อความ validation เดิมทั้งหมด · มือถือไม่เปลี่ยน
- ข้อความใหม่ที่ต้องเพิ่มใน spec: หัวกลุ่ม S06, "ปิดอัตโนมัติใน {n} วัน", คำสั้นช่วงวันที่ในปุ่มแบ่งช่อง ("7 วัน"), "สรุปการแจ้งซ่อม", "ครบ {n} จาก 5", "ไม่พบ{ชื่อช่อง}ที่ค้นหา"
