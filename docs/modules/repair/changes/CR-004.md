# CR-004 — หน้าแรก: เพิ่มเนื้อหาที่ไม่หนักและไม่รก

Status: PROPOSED   <!-- PROPOSED → APPROVED → DONE (or REJECTED) -->
Requested: 2026-10-14 by ผู้ใช้ (owner)
Size: S (scope) — อยู่ใน Stage 1, ไม่แตะ contract / DB; ดึงส่วนหนึ่งของ S02 จาก Stage 7 มาทำก่อน

## What changes

1. (รอบ 1) หน้าแรกช่วยหาอะไรมาใส่ที่ไม่หนัก และไม่รกมาก — ไปดูวิธีออกแบบที่คนอื่นทำไว้
2. (รอบ 2, 2026-10-15) ในหน้าแรกหาวิธีการออกแบบอื่นมา ระบบนี้จะมีการใช้งาน 3 บริการ ให้ออกแบบเผื่อไว้เลย

## Why

หน้าแรกตอนนี้ (placeholder Stage 0) มีแค่คำทักทาย การ์ดแจ้งซ่อม และปุ่มบริการ — desktop ว่างเกือบทั้งหน้า · หน้าแรกต้องรองรับแจ้งซ่อม จองรถ และจองห้องประชุม (PROJECT.md)

## Proposed design

รอบ 2 (ใช้แทนรอบ 1 `CR-004/home-options.html`): `CR-004/home-3-services.html` — ทุกแนวทางแสดง "ตอนนี้ (มีแค่แจ้งซ่อม)" และ "เปิดครบ 3 บริการ"

| แนวทาง | โครง | Claude แนะนำ |
|---|---|---|
| **1** | "ต้องดำเนินการ" (รายการที่รอคุณจากทุกบริการ แสดงเฉพาะเมื่อมี สูงสุด 3–4) + การ์ด 1 ใบต่อบริการที่เปิดแล้ว (เรื่องสำคัญที่สุด + ปุ่มเริ่ม + ดูทั้งหมด) + บริการที่ยังไม่เปิดย่อเป็นบรรทัด "เร็วๆ นี้" · desktop: ซ้าย = ต้องดำเนินการ + ปุ่มเริ่ม 3 บริการ, ขวา = การ์ดบริการ | **1** |
| **2** | "วันนี้ของฉัน": ปุ่มเริ่ม 3 บริการ + ไทม์ไลน์วันนี้/ถัดไปรวมทุกบริการ + งานซ่อมที่ยังเปิด · desktop: ปฏิทิน 5 วัน + การ์ดงานซ่อม | |
| **3** | ชิปสลับบริการแบบเป๋าตัง: แต่ละชิปเปิดแผงปุ่มลัด + รายการของฉันของบริการนั้น | |

ข้อมูลจองรถ / ห้องประชุมใน mockup เป็น **ตัวอย่างสมมุติ** — ยังไม่มีกติกา (brief ว่าง, ยังไม่รู้ว่าสร้างเองหรือลิงก์ไป Ploishared / WorkX)

สิ่งที่ขึ้นกับกติกาจองรถ / ห้องที่ยังไม่รู้: มีขั้นอนุมัติไหม (→ "ต้องดำเนินการ"), มีเช็กอิน / คืนกุญแจไหม, จองเป็นช่วงเวลาไหม, ใครจองได้, ระบบภายในหรือภายนอก (ภายนอก = การ์ดเป็นแค่คำอธิบาย + ลิงก์)

ส่วนเสริมที่ต้องมีข้อมูลจริงก่อน (ไม่ได้ใส่): แถบประกาศอาคาร, การ์ดเบอร์ติดต่อแม่บ้าน / รปภ. / ฉุกเฉิน
