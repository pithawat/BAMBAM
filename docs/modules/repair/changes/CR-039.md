## What changes

Owner (2026-11-09): "เพิ่มให้แต่ละ Case สามารถ กด save เป็น PDF และสร้างเป็น Qrcode สำหรับสแกน Qrcode เพื่อติดตามงานได้ ก็คือหน้ารายละเอียดงานซ่อมนั่นแหละ แต่เปลี่ยน template ใหม่ให้เป็นรูปแบบตัวอย่างที่ส่งให้ไป"

S07 ticket detail: every ticket can be saved as a PDF. The PDF replaces the current print report (CR-009 / CR-011 / CR-019 `@media print`) with the layout of the owner's sample (`report template.pdf`, attached in chat 2026-11-09; copy to be stored in `changes/CR-039/`):

- Header: app logo left · title `รายงานการดำเนินงาน` + `หมายเลขรายการ: {ticketNo}` right · QR top-right · primary-colour rule under the header.
- Body: titled sections (`ข้อมูลทั่วไป`, then one section per step of the job), each a bordered key / value table (grey label cells, bold values, status as a pill).
- Footer on every page: `เอกสารนี้ถูกสร้างโดยระบบอัตโนมัติ | วันที่พิมพ์: {date time}` · `หน้า {n}/{total}` · brand.
- QR = link to this ticket's S07 page (`{FRONTEND_URL}/repair/tickets/{id}`). Scanning opens the tracking page; not signed in → S01 login → back to the ticket (existing `?next=`); no access → the existing S07 forbidden state.

The sample's own product name / logo / brand text are not copied; BAMBAM's logo and name are used.

## Why

A shareable / filed document per case that anyone holding the paper can scan to see the live status.

Risk / notes:

- Browser print-to-PDF: page footer `หน้า n/total` needs CSS `@page` margin boxes (Chrome / Edge 131+; Safari / Firefox show no page number). iPhone "Save as PDF" goes through the share sheet.
- A generated file (client library or server) gives the same output on every device but costs a new dependency and Thai font embedding.
- Photos and the sign-off lines (ผู้แจ้ง · ผู้ซ่อม · ผู้อนุมัติ) are in the current print report but not in the sample — owner decides.

Owner answers 2026-11-09 (interview):

1. PDF = the browser print dialog ("Save as PDF"); no new library, no new endpoint → **no API / DB change**. `หน้า n/total` via `@page` margin boxes (Chrome / Edge); other browsers omit it.
2. Sections follow the job steps: `ข้อมูลทั่วไป` (สถานะ · เลขงาน · หมวดงาน · ผู้แจ้ง · อีเมลผู้แจ้ง · แจ้งเมื่อ · ระยะเวลาดำเนินการ) → `แจ้งซ่อม` → `รับเรื่อง / ประเมิน` → `ดำเนินการซ่อม` → `ผลการซ่อม` → `ประเมินผล`; a step with no data yet is left out. Same visibility rules as the S07 timeline (no priority for reporter / follower).
3. Keep photos (ก่อนซ่อม / หลังซ่อม) under their section. **Drop** the sign-off lines and the full history table.
4. QR only in the PDF (no QR button on screen).
