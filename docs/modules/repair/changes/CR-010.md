# CR-010 — Top navigation and white leopard mascot

Status: APPROVED (2026-10-18) · applied in Stage 2N
Requested: 2026-10-18 by project owner
Size: M

## What changes

Replace the shared desktop sidebar with a floating white top navigation inspired by the supplied `navbar.png`. Create a new transparent white leopard bust for the brand. A standalone interactive design proposal is at `output/navbar-redesign/index.html`; it is not wired into the application.

- Revised by owner feedback (2026-10-18): no mascot in the navbar. Desktop uses the existing BAMBAM wordmark, Home and three equally weighted service destinations (repair, car booking, room booking), notifications and account. No repair CTA or repair tracking link in global navigation. The selected service alone receives the active indicator.
- Services use equal label sizing, spacing and card treatment. Car/room navigation opens a clearly labeled unavailable-service preview, with no booking form or fabricated workflow. Production availability remains unchanged until their modules are built.
- Staff menus preserve the existing role visibility and destinations. Do not invent permissions or implement pending pages.
- Mobile/tablet: compact brand/utility row and a visible row of three equal service destinations; no sidebar or repair-centric global bottom navigation. Preserve route-local back buttons and form actions. This proposed replacement of the current bottom navigation is part of the approval scope.
- Account dropdown retains profile and existing logout confirmation. Production must never show the development role switcher.
- Content gains the sidebar width, while forms/details retain their readable maximum widths. Remove sidebar-shaped loading placeholders and print offsets.
- Keep the new mascot asset in `public/brand` for later approved placements; it appears nowhere in the proposed navbar. Broader replacement of existing mascot poses is outside this proposal.

## Why

The owner requested no sidebar, improved UX, a polished UI following `navbar.png`, and a cute white leopard mascot conveying speed. Short primary navigation makes frequent destinations visible while keeping role-specific tools grouped.

- Top navigation has less horizontal room. Use a second row of three equal service links on mobile; do not shrink touch targets or clip Thai labels.
- Existing sidebar points to pending admin pages. Preserve destinations without implying this CR implements those pages.
- Scope the active state carefully on ticket details, reporting and staff routes; no guessed ownership of a detail route.
- Menus must close on selection, outside click and Escape, return focus on Escape, and support keyboard navigation with visible focus.
- The revised preview shows general-user navigation, connected list/detail pages and local interaction demos, not authentication, live role switching, API actions or logout. Staff tools remain an implementation regression requirement.
- Existing approved design system limits mascot placement to success/empty/forbidden screens; no navbar mascot placement is proposed. Sidebar removal and the neutral mobile navigation require explicit approval.
- HANDOFF currently says BUILT BY CLAUDE; production implementation needs the approved rework scope and explicit shared-file ownership recorded before coding.
