1. **งานซ้ำ (F03)** — เตือนตั้งแต่ตอนกรอกฟอร์ม (ขั้นสถานที่) · ถ้าข้ามไป ตอนกดส่งต้องเจออีกครั้ง และบังคับให้ "ติดตามเคสเดิม" หรือ "ยกเลิกการแจ้ง" เท่านั้น (ไม่มี "ไม่ใช่เรื่องเดียวกัน ส่งเป็นงานใหม่") · งานของตัวเองที่ซ่อมเสร็จแล้วรอประเมิน: สร้างใหม่ไม่ได้ พาไปหน้าติดตามงานนั้น (ประเมินหรือส่งกลับให้แก้ที่นั่น)
   - Follow-up answer: "ซ้ำ" = same category + same floor **+ same room / spot** (a different spot on the same floor can be reported).
2. **ทีมแก้เอง (F04)** — เลือกตั้งแต่เปิดฟอร์ม "ทีมแก้เองแล้ว" หรือ "เรียกช่าง" · เห็นเฉพาะคนที่มีสิทธิ์
3. **เหตุผลที่เลื่อนวันเสร็จ** — ไม่บังคับ ผู้แจ้งเห็น (already in CR-008, no change)
4. **ขั้นตอนและคำเรียก:** แจ้งงาน → รับเรื่อง → กำลังดำเนินการ → เสร็จ → ประเมินตรวจงาน
   - ส่งฟอร์มแล้วเป็น "รับเรื่อง" ทันที งานขึ้นที่ช่าง (คนเดียว) เลย
   - ช่างกำหนดวันเสร็จ + ใครซ่อม → "กำลังดำเนินการ" · technician button **"เริ่มดำเนินการ"** (follow-up answer)
   - ชื่อผู้ซ่อมขึ้นหลังกำหนดวันเสร็จ
   - ปุ่มผู้แจ้ง "ให้คะแนน" → **"ประเมินตรวจงาน"** — still 1–5 stars, no default, send back allowed (follow-up answer)
   - ส่งกลับแล้วแสดงเป็นขั้น "ส่งกลับให้แก้"
5. **เก็บไว้ทั้งหมด:** ที่เคยแจ้ง, แบนเนอร์ QR, การกู้ข้อมูลที่กรอกค้าง (no change)
6. **S07 layout (2026-10-18):** "ticket-detail.html เอาเวอร์ชันนี้" — the file as it is on disk (demo-05 layout), replacing the CR-008 one-column spec

## Why

Follow the user flow the business uses; one wording for every role; stop duplicate tickets reaching the single technician.
