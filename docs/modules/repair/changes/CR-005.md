# CR-005 — ช่างคนเดียว ประเมินงานก่อนเริ่ม ช่างนอกระบบ และให้ดาวบังคับ

Status: APPROVED (2026-10-15) — applied, waiting for stage acceptance   <!-- PROPOSED → APPROVED → DONE (or REJECTED) -->
Requested: 2026-10-15 by ผู้ใช้ (owner)
Size: L — changes the main status flow and the data model across Stages 1–4; re-plan from Stage 1

## What changes

ผู้ใช้ (2026-10-15):

1. หลังผู้แจ้งแจ้งซ่อมเสร็จ สถานะขึ้นว่า **"กำลังดำเนินการ" ทันที** แล้ว**รอช่างมาประเมินงานก่อนเริ่มงาน**
   - ช่างประเมิน = บันทึก **วิธีดำเนินการ** (ช่างในระบบทำเอง / จ้างช่างนอกระบบ) + **วันที่คาดว่าจะเสร็จ**
2. จากนั้นเป็นสถานะ **"เสร็จ"** ช่างแนบรูปผลลัพธ์งาน แล้วผู้แจ้ง**ประเมิน**
   - ตั้งใจให้พนักงานประเมินให้ได้มากที่สุด: ตรวจรับ = **ดาว 1–5 บังคับ**; ยังไม่เรียบร้อย → ส่งกลับให้ช่างแก้ได้
   - **ปิดงานอัตโนมัติภายใน 3 วัน** หลังขึ้นสถานะเสร็จ (เหมือนเดิม)
3. **ช่างในระบบมีคนเดียว** → งานเข้าที่ช่างเลย ไม่มีกดรับงาน ไม่จำกัดทีละงาน
4. ช่างในระบบ**จ้างช่างนอกระบบ**ได้
   - ช่างในระบบเป็นคนกรอกข้อมูลช่างนอก (รวม **ประเภท** — เลือกจากรายการหรือเพิ่มใหม่เองได้)
   - ช่างในระบบเป็นคน**ให้คะแนนช่างนอก**ต่องาน
   - Admin เห็นประวัติงานและคะแนนของช่างนอกแต่ละเจ้า
5. เปลี่ยนฟีเจอร์แจ้งซ่อม และติดตามงาน (ฝั่งผู้แจ้งและฝั่งช่าง) จาก mock ไปใช้ API จริง; **ยังไม่ต้องทำเทส**

## Why

ผู้ใช้: ทีมจริงมีช่างคนเดียว ส่วนหนึ่งของงานจ้างช่างภายนอก ต้องการเก็บประวัติและคุณภาพของช่างนอก และอยากได้คะแนนจากพนักงานให้มากที่สุด

## Proposed rules (Claude — confirm or correct before approval)

**Statuses** (reporter sees one label "กำลังดำเนินการ" for both sub-steps; the tracker shows the step)

| Status | ป้าย | เข้าเมื่อ | ออกเมื่อ |
|---|---|---|---|
| `in_progress` + not assessed | กำลังดำเนินการ · รอช่างประเมิน | แจ้งซ่อม, ส่งต่อจากทีม (F05) | ช่างประเมิน, Admin ปิด |
| `in_progress` + assessed | กำลังดำเนินการ · กำลังซ่อม (คาดว่าเสร็จ {date}) | ช่างประเมิน, ผู้แจ้งส่งกลับ | ช่างบันทึกผล, Admin ปิด |
| `resolved` | ซ่อมเสร็จ รอประเมิน | ช่างบันทึกผล | ผู้แจ้งตรวจรับ (ดาวบังคับ) / ส่งกลับ, ปิดอัตโนมัติ 3 วัน, Admin ปิด |
| `closed` | ปิดงานแล้ว | ตรวจรับ, ทีมทำเอง, ปิดอัตโนมัติ, Admin ปิด | ส่งต่อช่าง (งานทีม) |

`new` is removed. Send back → `in_progress` (assessed) again; the assessment stays and the technician may change it.

**Technician (any user with role `technician`; phase 1 has one)**
- Sees every ticket that is not closed, priority → oldest first; filter by step (รอประเมิน / กำลังซ่อม / รอผู้แจ้งประเมิน) and building
- Assess: method (`in_house` / `contractor` + pick or add a contractor) + expected finish date (today or later) — both required; can be edited while `in_progress` (timeline event each time)
- Resolve: what was done + ≥ 1 result photo (as before); if method = contractor → **contractor rating 1–5 required** + optional comment
- Removed: claim, one-job-at-a-time, give back, reserved jobs (CR-001), categories per technician

**Contractors (ช่างนอกระบบ)**
- Fields: ชื่อร้าน / บริษัท (required), ประเภท ≥ 1 (required, many), ผู้ติดต่อ, เบอร์โทร, หมายเหตุ, active flag
- Types: technician picks from a list or adds a new type inline (unique, case-insensitive)
- Technician creates / edits contractors; Admin + executive view list (jobs count, average score) and per-contractor history (ticket, date, score, comment); no delete — deactivate
- Reporter sees "ดำเนินการโดยช่างภายนอก · {ประเภท}" — **not** the contractor's name / phone / score

**Reporter**
- Confirm needs 1–5 stars (comment optional); send back needs a reason (+ optional photos) — as before
- Auto-close 3 × 24 h after `resolved`, no rating

**Admin**
- Sees all tickets, changes priority, closes any ticket (unchanged); **manual queue reordering is removed** (no queue any more — supersedes D-006 reorder)
